## 特征工程

### 重要性
**特征工程是最有效的提分点。** 当前特征回答的是"环境有什么"，需要改成回答"我现在危险不危险、有没有机会、往哪走安全"。

### 建议增加的特征分组

| 特征组 | 建议内容 | 作用 |
|--------|---------|------|
| **英雄主特征** | 当前位置状态、分数进展、闪现是否可用、当前阶段、是否卡住、是否绕路 | 回答"我现在什么状态" |
| **宝箱特征** | 宝箱方向和距离、是否有效、危险度、是否值得追 | 回答"哪个资源值得追" |
| **怪物特征** | 最近距离（**用离散距离桶而非欧式距离**）、第二只怪位置（非常重要！两只怪合围才是真正危险）、怪物加速倒计时 | 回答"危险从哪来" |
| **技能/buff特征** | 闪现可用性、buff状态、该贪还是该保 | 回答"还有没有操作空间" |
| **地形特征** | 各方向通路长度、有没有死角、长走廊、开阔区域 | 回答"往哪走更安全" |

### 关键洞察
1. **距离用离散桶**：环境提供了 `hero_l2_distance`（0-5的离散桶），而不是自己算欧式距离。在迷宫地图里，离散距离对决策更有意义。
2. **后期地形更重要**：后期不是单纯知道怪物近就够了，更重要的是知道附近有没有开阔区域、有没有长走廊、有没有死角。

## 奖励函数

### 核心思路
根据游戏阶段调整策略：前期更鼓励拿资源 + 稳定推进，后期更鼓励保命 + 拉空间。

### 前后期拆分

#### 前期（怪物未加速）
| 奖励项 | 类型 | 说明 |
|--------|------|------|
| 宝箱接近奖励 | 稠密 | 比较到最近宝箱的距离，在接近时给正向奖励 |
| 宝箱分奖励 | 稀疏 | 吃到宝箱才触发 |
| 步数分奖励 | 稠密 | 步数得分上涨时触发 |

#### 后期（怪物加速后）
| 奖励项 | 类型 | 说明 |
|--------|------|------|
| 怪物距离 shaping | 稠密 | 提高权重，远离怪物正奖励 |
| corridor奖励 | 稠密 | 位置越开阔、越容易拉扯，奖励越高 |
| 死角惩罚 | 稠密 | 当前位置像死角或短胡同，惩罚越重 |
| 包夹惩罚 | 稠密 | 两只怪物合围趋势时惩罚 |

### 贯穿全程的关键奖励

| 奖励项 | 类型 | 说明 |
|--------|------|------|
| 生存奖励 | 稠密 | 每一步固定给一个基础 reward，保证模型在没有拿到显式收益时也能收到"先活着"的信号 |
| 步数分奖励 | 稠密 | 比较当前帧和上一帧的步数得分，只在步数得分真的上涨时给正向奖励 |
| 宝箱分奖励 | 稀疏 | 比较当前帧和上一帧的宝箱得分，只有真的吃到宝箱、宝箱分上涨时才触发 |
| buff奖励 | 稀疏 | 比较当前帧和上一帧拿到的 buff 数量，拿到新 buff 时触发 |
| 宝箱接近奖励 | 稠密 | 比较当前帧和上一帧到最近宝箱的距离，如果确实在接近宝箱，并且当前局面不太危险，就给正向奖励 |
| 怪物距离 shaping | 稠密 | 比较当前帧和上一帧到最近怪物的距离，离怪物更远就加分，离怪物更近就减弱甚至变成负反馈 |
| 临近加速缓冲奖励 | 稠密 | 当怪物快要进入加速阶段时，根据和最近怪物、第二只怪物的距离，提前鼓励模型给自己留安全空间 |
| 后期生存奖励 | 稠密 | 怪物进入加速阶段后，明显提高"和怪物拉距离""维持安全空间"这类项的重要性 |
| corridor奖励 | 稠密 | 根据当前位置周围几个方向的通路长度、平均可走深度以及附近区域是否开阔来算，位置越开阔、越容易拉扯，奖励越高 |
| 包夹惩罚 | 稠密 | 根据两只怪物和自己的相对位置关系来判断是否有合围趋势，如果活动空间被两只怪一起压缩，就惩罚 |
| 死角惩罚 | 稠密 | 根据当前位置附近是否开阔、内圈是否容易转身来判断，越像死角或短胡同，惩罚越重 |
| 危险惩罚 | 稠密 | 直接看最近怪物距离是否低于阈值，怪物越近惩罚越重；加速后同样的距离会更危险 |
| 撞墙/无效移动惩罚 | 稀疏 | 如果这一动作之后几乎没有产生有效位移，说明走到了墙上或者做了无效动作，就触发惩罚 |
| 重复探索惩罚 | 稠密 | 根据最近一段时间是否一直在老区域里来回绕圈来算，重复绕得越久，惩罚越明显 |
| 闪现脱险奖励 | 稀疏 | 如果使用闪现后，和怪物的距离明显拉开，或者自己到了更安全、更开阔的位置，就给奖励 |
| 闪现滥用惩罚 | 稀疏 | 如果使用闪现后既没有明显脱险，也没有改善站位、拿到资源，就给惩罚 |
| 第二只怪压力惩罚 | 稠密 | 单独看第二只怪的距离，如果第二只怪压得过近，就额外补一层惩罚，避免模型只盯最近那只怪 |
| 终局奖励 | 稀疏 | 在 episode 结束时统一结算，正常完成、异常截断、阵亡分别给不同终局信号 |

### 最关键的奖励项
1. **怪物距离 shaping**：最核心的生存信号之一，尤其影响后期质量
2. **宝箱分奖励 / 宝箱接近奖励**：前期拿资源的主要驱动力
3. **临近加速缓冲奖励**：影响模型能否顺利过渡到高压阶段
4. **corridor 奖励 + 死角惩罚**：对后期是否容易暴毙帮助很明显
5. **闪现脱险奖励**：把闪现学成"保命技能"而不是乱交技能
6. **后期生存奖励**：怪物加速后需要大幅提高生存相关奖励的权重

## 网络结构

### 当前问题
简单的 MLP 拍扁输入，没有利用空间结构信息。

### 建议结构
- 标量特征 → MLP
- 局部地图(21×21) → CNN 或 空间编码
- 多个实体（宝箱、怪物、buff）→ 分别编码后做融合

### 关键思路
不是把所有输入糊成大向量，而是拆成几部分处理：
1. 英雄自身状态
2. 宝箱信息
3. 怪物信息
4. buff/技能信息
5. 局部地图信息

### 多头注意力（Multi-Head Attention）
让模型自己决定当前更该看哪类实体——**前期更容易把注意力放在资源上，后期更容易切到怪物和逃生空间**。

**实现方式**：
- 先把宝箱、怪物、buff 等实体各自编码成 embedding
- 用多头注意力让模型自己决定当前更关注哪类实体
- 不同的 head 可以关注不同的方面（危险距离、资源位置、地形安全等）

**优势**：
- 动态调整注意力权重，前期关注资源，后期关注逃生
- 比静态特征更能适应不同场景

## 动作空间扩展

### 当前问题
只用了移动(0-7)，闪现(8-15)没用。

### 建议
扩展为完整的16维动作空间：
- 闪现是**保命技能**，不是用来赶路的
- 需要设计对应的闪现奖励，让模型学会"用得值"而不是"乱交"

## 训练流程优化

### Train/Val Split（强烈建议）

按地图拆分：
- 训练地图：1~8
- 验证地图：9~10
- 每隔10个episode跑1局val

**经验：** "很多改动看起来train在涨，但val根本没涨，只做训练题"

### Curriculum Learning（课程学习）

> **重要**：以下配置来自经验贴的参考值。虽然评估时环境参数固定，但课程学习仍然重要——它能帮助模型学会在不同压力阶段切换策略（前期拿分 vs 后期保命），提高整体表现。

分阶段调整环境难度：

| 阶段 | 宝箱数 | buff数 | 第二只怪出现 | 怪物加速 | 最大步数 |
|------|--------|--------|-------------|---------|---------|
| warmup (0-150ep) | 9~10 | 2 | 220~300 | 360~460 | 2000 |
| mid_pressure (150-500ep) | 8~10 | 1~2 | 160~280 | 240~420 | 2000 |
| late_speedup (500-900ep) | 7~10 | 1~2 | 120~220 | 180~320 | 2000 |
| hard_generalization | 6~10 | 0~2 | 120~320 | 140~420 | 2000 |

**思路：** 前面让模型在资源多、压力低的环境学会推进；后面逐步增加难度，逼模型从"会拿分"过渡到"高压下也能活"。

**替代方案**：由于评估参数固定，也可以考虑直接使用固定参数训练，简化流程。

## 监控指标

### 重要性
需要关注**前后期差异**，很多问题会被平均值掩盖。

### 建议监控的指标

#### 前后期拆分看的指标
- Pre_Steps / Post_Steps（加速前/后走了多少步）
- Pre_TotalR / Post_TotalR（加速前/后累计奖励）
- Post_Terminated（是否在加速后阶段阵亡）

#### 关键比率
- TerminatedRate（阵亡比例）
- CompletedRate（正常完成比例）

#### 算法指标
- CumReward、TotalLoss、ValueLoss、PolicyLoss、EntropyLoss
- ClipFrac、ExplainedVar、AdvMean、RetMean

## 核心思想

这题的关键不是某一个模块特别花，而是：

> **让模型真正学会在"拿资源"和"保命"之间切换。**

- 特征要同时把"危险"和"机会"说清楚
- 奖励要引导模型在合适的时机做合适的决策
- 前后期目标不同，需要差异化处理
